# AI 共创场

一个把“每个人各自用 AI”变成“团队一起用 AI 共创”的现场活动工具。

它解决的不是让 AI 多写一份内容，而是让 3–12 人围绕同一个问题，在有限时间内完成两轮思考、匿名互评、交流和结果沉淀。主持人不必在聊天群、计时器、投票表和文档之间来回切换；参赛者只需打开链接，使用自己熟悉的 AI 工具完成回答。

项目默认不绑定任何大模型账户，也不要求 API Key；它不会替使用者调用任何模型或产生模型费用。

## 当前公开版本状态

**当前 `main` 是不完整的源码快照，不能直接安装、启动或部署完整活动应用。** 下文的活动流程和五类入口描述的是产品设计与历史实现，不代表当前公开分支已支持这些功能。

截至 2026 年 10 月 8 日，仓库仅保留 README、活动创建首页与表单、活动创建领域逻辑、D1 活动存储适配器及两份测试。可独立运行活动创建逻辑测试；浏览器界面与完整多人活动流程尚不可运行。

## 它带来的价值

- **把个人 AI 使用变成团队共创**：每个人先独立生成，再用一次追加 Prompt 改进，避免讨论一开始就被少数声音带走。
- **让活动有清晰节奏**：候场、作答、匿名投票、交流、结果逐段推进；主持人手动掌握时间，阶段结束后内容锁定。
- **让好想法被看见**：匿名互评降低身份影响，结果、特色奖项和完整报告会在活动结束后保留。
- **不绑定工具选择**：参与者可使用任何 AI；默认按互评票数公布，也可把匿名作品交给自己的 AI 工具做补充评分。

## 适合什么场景

- 团队 AI 共创、Prompt 挑战或工作坊
- 3–12 人、1–2 轮的现场活动
- 主持人手动控时，希望参赛者通过链接直接加入
- 希望先用互评形成结果，再按需加入外部 AI 评分

## 第一次如何使用

主持人只需完成下面五步：

1. 通过组织者入口创建一场 1–2 轮、3–12 人的活动，保存主持人、参赛者、大屏和报告入口。
2. 将参赛者链接和房间码发给大家；参赛者填写昵称和自己使用的 AI 工具名称后加入候场。
3. 在主持人入口播放开场词或人工介绍，确认至少 3 人后点击“启动第一版并锁定名单”。
4. 现场根据页面进度和自己的计时器，依次结束各阶段；参与者始终只需要在当前页面完成当前动作。
5. 最后按互评结果公布，或可选地复制/下载匿名作品交给自己的 AI 工具评分后回填；从报告入口下载活动记录。

## 活动流程

1. 组织者创建活动，保存主持人、参赛者、大屏和报告入口。
2. 参赛者通过活动链接和房间码加入候场；同一浏览器可自动恢复席位。
3. 主持人播放浏览器内置语音开场或复制开场词人工介绍，然后锁定名单。
4. 参赛者完成 V1、一次追加 Prompt 与 V2；每次阶段结束后内容锁定。
5. 所有人匿名投出最喜欢的作品，不能投给自己。
6. 主持人可直接按互评票数公布结果；自由交流由主持人手动结束。
7. 如需补充评分，可一键复制或下载整轮匿名作品，交给任意自有 AI 工具评分，再把 0–10 的分数回填。
8. 活动结束后下载整场 JSON 报告，包含题目、作品、投票、可选外部评分和总成绩。

默认规则是：**单轮成绩 = 获得的互评票数**。只有主持人主动回填外部评分时，单轮成绩才变为“外部评分 + 互评票数”。

## 参赛者在页面上做什么

1. 在候场页输入昵称和所用 AI 工具名称，点击加入。
2. 第一版阶段：阅读题目，在自己的 AI 工具中思考，将答案粘贴回页面并点击保存。
3. 改进阶段：填写一次追加 Prompt，再保存改进后的 V2 答案。
4. 匿名互评阶段：阅读其他作品，投出一票最喜欢的作品，不能投给自己。
5. 身份揭晓后参与自由交流，最后查看结果和奖项。

请注意：主持人点击阶段结束后，未保存的内容不能补交，也不能返回修改。

## 五类页面入口

活动创建完成后，系统会为同一场活动生成不同用途的入口。请不要把所有入口都发给所有人：

| 页面 | 谁使用 | 主要操作 |
| --- | --- | --- |
| 组织者配置页 | 活动组织者 | 创建活动、配置人数与轮次、复制上一场配置、下载组织者全量报告 |
| 主持人页 | 现场主持人 | 播放或复制开场词、锁定名单、手动推进每个阶段、结束自由交流、公布结果 |
| 参赛者页 | 参赛者 | 加入候场、填写昵称与 AI 工具名称、提交 V1/V2、参与匿名互评 |
| 现场大屏页 | 投影屏幕或旁观者 | 展示活动状态、当前轮次、匿名作品、投票结果、排名与奖项 |
| 活动报告页 | 活动参与者或查看者 | 查看匿名活动报告；组织者入口另有全量导出 |

最简单的现场分工是：组织者负责创建并保存链接，主持人只使用主持人页，参赛者只使用参赛者页，投影电脑打开现场大屏页。活动链接和房间码一起发给参赛者即可。

## 本地检查与测试

当前仓库没有 `package.json`、`package-lock.json` 或启动配置，因此 **`npm ci`、`npm run dev`、`npm test` 和 `npm run lint` 均不可用**，也没有可访问的本地预览地址。仅配置 Cloudflare D1 的 `DB` 绑定不能解决这些缺失。

如需检查现有代码，可以使用支持 TypeScript 类型擦除的 Node.js（建议 Node.js 22.13.0 或以上），无需安装 npm 依赖：

```bash
git clone https://github.com/gary2222hub/ai-cocreation-arena.git
cd ai-cocreation-arena
node --experimental-strip-types --test tests/activity-creation.test.ts
```

这条命令验证活动创建、参数校验、邀请码与公开创建、入口权限隔离及配置复制逻辑。2026 年 10 月 8 日在 Node.js 24.19.0 下验证，7 项测试全部通过；它不验证浏览器页面或真实 D1 环境。

`tests/d1-activity-store.test.ts` 目前不能运行：它依赖已缺失的 `src/d1-live-event-store.ts`、`src/d1-lobby-store.ts`、`src/lobby.ts` 及数据库迁移文件。因此请勿把单份领域测试通过理解为完整应用已通过验证。

## 部署与数据边界

当前公开分支不支持直接部署。历史实现使用 Cloudflare D1 数据库绑定 `DB`，但当前缺少 API、数据库迁移和部署配置，包括 `.openai/hosting.json`。

- 不要把 `.env`、活动链接、房间码或参会者导出数据提交到仓库。
- 现有代码不内置任何模型供应商或 API Key；产品设计中的外部 AI 评分由活动使用者自行选择和执行。

## 当前项目结构

- `app/page.tsx` 与 `app/create-activity-form.tsx`：活动创建首页与表单；依赖的页面运行环境和 API 未包含在当前分支中。
- `src/activity-creation.ts`：活动创建、配置校验、入口权限与内存存储实现。
- `src/d1-activity-store.ts`：D1 活动存储适配器；需要数据库结构与 D1 运行环境。
- `tests/activity-creation.test.ts`：可独立运行的活动创建逻辑测试。
- `tests/d1-activity-store.test.ts`：依赖缺失实现与迁移的 D1 测试，当前不可运行。

当前分支没有 `db/`、`drizzle/`、`docs/adr/` 或完整的主持、参赛、大屏、报告页面。
